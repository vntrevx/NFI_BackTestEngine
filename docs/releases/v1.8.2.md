# NFI Backtest Engine v1.8.2

v1.8.2 repairs the installed product's first-run experience. A fresh NFI checkout no
longer requires users to understand, copy, or flatten Freqtrade's modular JSON before
the first backtest.

## Mode-first setup

Running the strategy directly now starts with the choice that determines the runtime
contract:

```bash
nfi-bte run NostalgiaForInfinityX7.py
```

When no self-contained Freqtrade config is available, the wizard:

1. asks for Spot or Futures;
2. asks for the CCXT exchange and pair list;
3. writes a credential-free dry-run config under `.nfi/`;
4. selects a managed candle directory and timerange;
5. saves the reusable project before data preparation.

The generated config uses one open trade, an empty credential set, StaticPairList, and
the selected mode's market type. Futures uses isolated margin. The selected pairs are
stored in the project and injected into the sealed effective run config.

## Existing configuration boundary

Existing valid standard configs are still detected. An explicit `--config` remains
strict: parent-traversing includes, symlinks, malformed JSON, missing exchange identity,
and a mismatch with `--trading-mode` fail closed. The wizard never rewrites an upstream
or user-owned config. Only the engine-owned `.nfi/first-run-config.json` is generated.

Non-interactive setup can select the same path without manual JSON:

```bash
nfi-bte run NostalgiaForInfinityX7.py \
  --trading-mode spot \
  --pair ADA/USDT \
  --timerange 20260101-20260108 \
  --yes
```

## Verification

Regression coverage reproduces an NFI-style `user_data/config.json` containing
`../configs/...`, proves that the interactive flow asks for mode before configuration,
and validates generated Spot and isolated-Futures configs. Separate tests retain the
strict explicit-config rejection and CLI non-interactive path. The actual PTY wizard
was exercised with X7 v17.4.587 through project creation.

## Certification and distribution boundary

This patch does not change simulation semantics or certification scope. The bounded
X7 v17.4.585 Spot and Futures Official/Native evidence remains exact at zero tolerance.
The five-year certificates remain independently bound to v1.0.0 and v1.1.0, and
`combined_full_x7_certified` remains false.

Release publication remains build-once: SHA-256-sealed artifacts, required-CI commit
matching, exact fixture evidence for Linux and macOS, and byte-identical promotion
from the release candidate to the stable tag. Linux x86_64 and aarch64 and macOS arm64
remain the supported release targets. Windows users run the Linux build under WSL2.
