# NFI Backtest Engine v1.10.2

v1.10.2 makes completed-run reuse explicit and preserves prior evidence when the user chooses fresh work. Native simulation semantics are unchanged.

## Completed-run choice

When the saved output contains a completed run, interactive `nfi-bte run` now asks:

```text
Start a new backtest with the same saved settings? [y/N]:
```

- Enter or No reuses the completed result. No input preparation or simulation starts.
- Yes selects a fresh sibling output such as `<previous>-new`, then shows the normal CPU worker confirmation.
- Cancelling the CPU confirmation leaves the saved project pointed at the completed output.
- Approving execution retargets the project to the fresh output; the completed output remains untouched.

Unattended `--yes` keeps the deterministic reuse behavior. Use `--new-run --yes` to request a fresh output explicitly in automation.

## Evidence boundary

Fresh execution never clears or overwrites the completed directory. Existing Spot and Futures certificates remain bound to their original release evidence, and this CLI workflow release makes no new continuous performance claim.

## Upgrade

```text
nfi-bte update
nfi-bte --version
```

The reported version must be `nfi-bte 1.10.2`.
