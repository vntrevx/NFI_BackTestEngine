# NFI Backtest Engine v1.7.0

v1.7.0 completes materialized semantic tracing and refreshes the product boundary for
current NFI X7 without overstating the existing continuous certificates.

## Complete semantic traces

Official Freqtrade traces now retain both open and closed trades in the versioned
`reference-state-v2` state document. Native and Official traces retain complete
materialized records at their own callback and event granularities. Their raw event
counts and schemas are not claimed to be one-to-one.

Exact parity uses the common every-candle projection. Wallets, trades, orders,
protections, realized profit, and counters compare with zero numeric tolerance. A
single bounded-memory migration permits an immutable legacy expected trace—which
omitted open trades—to be checked against a v2 fresh trace. Reversed, unknown, or
malformed schema transitions fail closed.

## Current X7 product identity

The release qualification freezes NostalgiaForInfinity X7 v17.4.580 at upstream
commit `b22cc60d1c018eeb984cb02a125bb790042bebd0`, source SHA-256
`40796e8be7ad11ba14dc51607ee1d002d1c7cce743f1476f67ddfac5283a5aeb`.
Spot and Futures static reachability checks report zero reachable stateful gaps,
complete closure, and Native compatibility. This is source-compiled closure evidence,
not a new full-state or continuous performance certificate.

Distribution regression remains bound to the immutable v17.4.473 Spot and Futures
release-candidate fixtures in `.github/release-candidate-contract.json`. Keeping the
current upstream qualification separate from the historical regression identity
preserves reproducibility while the runtime continues to fail closed on unknown
active semantics.

## Certification boundary

This is a product release with `combined_full_x7_certified=false`. The five-year Spot
and Futures certificates remain independently bound to v1.0.0 and v1.1.0,
respectively. They are not a same-candidate Spot-versus-Futures certificate and are
not combined into a public 10/10 claim.

Release publication remains build-once: SHA-256-sealed artifacts, required-CI commit
matching, exact fixture evidence for Linux and macOS, and byte-identical promotion
from the release candidate to the stable tag. Linux x86_64 and aarch64 and macOS arm64
are the supported release targets. Windows users run the Linux build and ABI under
WSL2; native Windows fails closed with `native Windows is unsupported; run nfi-bte
under WSL2 (Linux)`.
