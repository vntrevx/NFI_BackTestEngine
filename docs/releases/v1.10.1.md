# NFI Backtest Engine v1.10.1

v1.10.1 makes CPU-intensive work explicit before `nfi-bte run` starts preparation or simulation. Native simulation semantics are unchanged.

## Confirmation before execution

- Interactive runs display the selected strategy, timerange, pair count, system readiness, and planned CPU worker count before asking whether to start.
- Enter defaults to No. Declining exits successfully without starting input preparation or the simulator.
- Non-interactive runs fail closed unless `--yes` is present. Explicit `--yes` remains the unattended execution contract.
- `--workers N` lowers the planned parallel worker count and is reflected in the prompt.

## CPU visibility

The persisted `.nfi/run-preflight.json` now records physical CPUs, logical CPUs, affinity-visible CPUs, and the derived safe worker limit. The compact readiness line distinguishes worker processes from visible logical CPUs.

The default worker limit remains `min(logical CPUs, physical CPUs, affinity-visible CPUs)`. Nested Rayon, OpenMP, OpenBLAS, MKL, and Polars thread pools remain capped at one thread per worker to avoid oversubscription; chronological portfolio simulation remains single-threaded.

## Evidence boundary

This CLI safety release does not change Native simulation semantics or claim a new continuous performance certificate. Existing Spot and Futures certificates remain bound to their original release evidence.

## Upgrade

```text
nfi-bte update
nfi-bte --version
```

The reported version must be `nfi-bte 1.10.1`.
