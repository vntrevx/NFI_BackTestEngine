# NFI Backtest Engine v1.8.1

v1.8.1 extends source-compiled NFI X7 compatibility through v17.4.585, reduces the
release-candidate verification cost, and bounds compatibility automation queues. It
adds exact current-source evidence without relabeling the existing continuous
certificates.

## Current X7 capability

The release qualification freezes NostalgiaForInfinity X7 v17.4.585 at upstream
commit `47f3b66f4767fe228a74a98f0d4a7e51199e1488`, source SHA-256
`ff061a8c113b29a599306044cbcc2112ac2eb901f458a55de82bf15f93875e22`.
Spot and Futures static reachability report zero reachable stateful gaps, complete
closure, and Native compatibility.

System-adjustment lowering now accepts exact local aliases of enable flags, exit
helpers, system-v3 class constants, candle features, Futures mode, trade side, and
liquidation operands. The aliases lower into the existing generic IR. Mismatched alias
shapes fail closed, and no strategy-version, source-hash, pair, timerange, or expected-
result branch was added.

## Independent bounded exact proof

Two compact fixtures compare independent Official Freqtrade and Native trade surfaces
and every-candle state at zero tolerance:

- Spot `ADA/USDT`, `20251104-20251107`: 864 state events, state-stream SHA-256
  `c4295cbc14d4cfce8f0dd089277e503128c14aca967da73eedcd934fa91f7c2d`;
- isolated-Futures `THETA/USDT:USDT`, `20251113-20251117`: 1,152 state events,
  state-stream SHA-256
  `b0d3e80edb7af377a63dfc526e24a7ac766c0bd0d27a620247a7cb017e1a22c4`.

The manifests are preserved in
`benchmarks/fixtures/captured/future-nfi-spot-v17.4.585-aliases-ada` and
`benchmarks/fixtures/captured/future-nfi-futures-v17.4.585-aliases-theta`. Their shared
identity is `benchmarks/evidence/future-nfi-v17.4.585-alias-compatibility.json`. These
bounded fixtures qualify the alias-compatibility change; they are not continuous
five-year certificates.

## Faster release verification

Fixture validation can retain descriptor-validated v3 coverage for downstream probes
instead of rereading and rehashing fixture paths. Validation-only tests explicitly
release retained payloads, and semantic-registry negative checks mutate then restore
the tested entry instead of copying the full registry six times. The local release-
candidate probe matrix fell from 94.28 seconds to a 53.57-second median across three
post-change runs, a 43.2% reduction on the measured host. This is workflow-cost
evidence, not a simulation performance claim.

## Bounded compatibility automation

Compatibility discovery now reconciles at most one automation-owned Draft candidate
per trading mode. A new immutable identity closes only stale automation-owned Drafts.
A non-Draft same-mode pull request remains human-controlled, is never mutated by the
automation, and blocks creation of another candidate. The blocker issue remains a
single reconciled issue. Automation still cannot approve or merge pull requests.

## Certification and distribution boundary

This remains a product release with `combined_full_x7_certified=false`. The five-year
Spot and Futures certificates remain independently bound to v1.0.0 and v1.1.0. They
are not a same-candidate Spot-versus-Futures certificate and are not combined into a
public 10/10 claim. The immutable historical release-candidate fixtures remain the
distribution regression identity.

Release publication remains build-once: SHA-256-sealed artifacts, required-CI commit
matching, exact fixture evidence for Linux and macOS, and byte-identical promotion
from the release candidate to the stable tag. Linux x86_64 and aarch64 and macOS arm64
are the supported release targets. Windows users run the Linux build and ABI under
WSL2; native Windows fails closed.
