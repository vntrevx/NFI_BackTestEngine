# NFI Backtest Engine v1.8.4

v1.8.4 corrects the beginner market-selection workflow introduced in v1.8.3.

## Exact market counts

The quick default is now `BTC/USDT` for Spot or `BTC/USDT:USDT` for isolated Futures. BTC has the longest practical history and X7 already requires its reference series, so the default does not add a second market download.

The interactive wizard accepts `1`, `10`, `20`, `40`, `80`, `100`, `all`, or `custom`. Scripts can use `--pair-count 1|10|20|40|80|100|all`; explicit symbols remain available through repeated `--pair` arguments.

For `10` through `100`, the engine runs the NFI checkout's current Binance volume and filter policy through the pinned Freqtrade image. It preserves that ranked order in `.nfi/project.json`, so downloads and simulation use the exact same frozen portfolio even if exchange volumes later change. Transient exchange failures receive three bounded attempts and write complete diagnostics to `.nfi/pair-selection-error.log` if exhausted.

Selections of 40 or more markets show a resource warning before candle preparation. It recommends the seven-day first run and states the measured boundary that an 80-pair five-year workload can require about 39 GiB of memory.

## Compatibility and evidence boundary

Simulation, exact-parity, and fail-closed contracts are unchanged. Pair ranking is initialization input discovery, not a runtime strategy branch. The independently sealed Spot and Futures certificates remain version-bound; this usability release does not claim a new combined or continuous performance certificate.
